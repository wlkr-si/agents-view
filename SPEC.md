# agents-view v0

An open convention for plain Markdown instruction files. This specification may be freely copied and implemented.

- The first line of `AGENTS.md` is `<!-- agents-view v0 -->`.
- A top-level `## Heading` starts a named section. Names are unique. Text before the first heading is the intro, addressed as `Intro` by tools.
- Infer the section type in order. A Mermaid fence makes a **diagram**. A section named `Overrides` whose list items are Override lines makes **overrides**. A list of Markdown links makes **pages**. Another bullet list makes **rules**. Other content is **text**.
- Every visual section carries agent-readable text. Mermaid diagram text qualifies. A future drawing type can link to a sibling drawing with a text equivalent immediately below the link.
- Keep the whole file to about 1,000 tokens. Estimate by dividing character count by four and rounding up. Tools warn when the estimate exceeds the budget.
- Put pointers to larger documents in `## Pages`. Each line is `- [Name](relative/path) — read when …`. Use the existing `CONTEXT.md` convention for a glossary. These are pointers for agents to follow when relevant.
- Put project-specific replacements in `## Overrides`. Each line is `- Global: "<exact global text>" → here: <replacement>`. Double quotes and backslashes can be escaped inside the quote. The replacement is the project instruction. A quote absent from every Global source is **STALE**.
- `AGENTS.md` is the only editable source of truth. Editors preserve the file outside the section they change.

Sources and their load order follow each agent's documentation (checked 2026-11-19). Each rule links its source. Where docs and observed behavior differ, the docs win and the difference is noted.

- **Claude Code** ([memory](https://code.claude.com/docs/en/memory)). Global `~/.claude/CLAUDE.md` and `~/.claude/rules/`, then from the filesystem root down to the working directory, per directory `CLAUDE.md` or `.claude/CLAUDE.md`, then `CLAUDE.local.md`. `AGENTS.md` is read as project instructions only when no CLAUDE file exists in that walk; if one exists, only CLAUDE files are read unless one imports `@AGENTS.md` (or the Project instructions setting is `claude-md-and-agents-md`). `@path` imports expand beside their importer, up to four hops. Subdirectory `CLAUDE.md` files are Nested, read when Claude touches a file there. Auto memory is the first 200 lines or 25 KB of `~/.claude/projects/<project>/memory/MEMORY.md`. Observed: 2.1.327 read `AGENTS.md` alone, as documented.
- **Codex** ([AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md), [memories](https://learn.chatgpt.com/docs/customization/memories)). Global `~/.codex` (or `CODEX_HOME`): `AGENTS.override.md`, else `AGENTS.md`, first nonempty. Then from the Git root to the working directory, per directory the first nonempty of `AGENTS.override.md`, `AGENTS.md`, then `project_doc_fallback_filenames`. Files join root-first, up to 32 KiB. No imports and no on-demand loading. Memories, off by default, live in `~/.codex/memories_v2/`.
- **OpenCode** ([rules](https://opencode.ai/docs/rules/)). Global `~/.config/opencode/AGENTS.md`, else `~/.claude/CLAUDE.md`. Then `AGENTS.md` from the workspace up to the project root, where a directory without `AGENTS.md` uses its `CLAUDE.md`; matching files combine. The config `instructions` list (paths, globs, URLs) loads after them. Files below the workspace are Nested, loaded as the agent reads there. No imports, no memory.
- **Gemini CLI** ([GEMINI.md](https://geminicli.com/docs/cli/gemini-md/), [imports](https://google-gemini.github.io/gemini-cli/docs/core/memport.html)). Global `~/.gemini/GEMINI.md`, then `GEMINI.md` from the working directory up to the `.git` root, then subdirectories below it, concatenated. Nested `GEMINI.md` files also load when a tool touches that directory. `AGENTS.md` is read only if `context.fileName` in `settings.json` lists it. `@file.md` imports nest up to five levels. Observed: 0.46.0 has no built-in `AGENTS.md` support.
- **Cursor** ([rules](https://cursor.com/docs/context/rules), [CLI](https://cursor.com/docs/cli/using)). Merge order Team, Project, then User rules; User rules are set in Cursor settings, not a file. Project rules are `.cursor/rules/*.mdc`; plain `.md` is ignored. `AGENTS.md` at the root and in subdirectories is read natively, and nested ones apply when working in that folder (Nested). The CLI also reads root `AGENTS.md` and `CLAUDE.md`. No memory is documented.
- **GitHub Copilot** ([support matrix](https://docs.github.com/en/copilot/reference/custom-instructions-support), [repository](https://docs.github.com/en/copilot/how-tos/configure-custom-instructions/add-repository-instructions), [CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-custom-instructions)). Modeled on the Copilot CLI and coding agent. Global `~/.copilot/copilot-instructions.md` and `~/.copilot/instructions/**/*.instructions.md` (`COPILOT_HOME` moves them; `COPILOT_CUSTOM_INSTRUCTIONS_DIRS` adds more). Project: `.github/copilot-instructions.md`, `.github/instructions/**/*.instructions.md` (by `applyTo`), and `AGENTS.md`, `CLAUDE.md` or `GEMINI.md`, from the repository root through the working directory and Nested ones near files being edited; the nearest `AGENTS.md` wins. The CLI expands `@relative/path` in `copilot-instructions.md`, `AGENTS.md` and `CLAUDE.md`, not in `GEMINI.md` or `*.instructions.md`. Other precedence between files is undefined. Copilot Memory is created by Copilot, not a file.

These rules model on-disk conventions. Runtime settings, managed and organization instruction sources, personal instructions set on websites, size truncation, and Copilot in other editors are outside this version.
